# netstat 工具包说明（NOTES）

> 目标程序：`C:\Windows\System32\NETSTAT.EXE`（文件版本 10.0.26100.8521）—— Windows 自带。
> 清单：动作 8 个 / 字段 19 个 / 字段出处标注 **100%**
> **公共事实见 [`docs/reference/win-commands-shared.md`](../../docs/reference/win-commands-shared.md)**。
> 实测环境：Windows 11 `10.0.26200`，账号 `KANGMORI\Steve`（非管理员）。

---

## 1. 参数知识来源（本包有一处重要的来源冲突）

| # | 来源 | 位置 |
|---|---|---|
| 1 | 官方文档 | `https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/netstat` → 快照 `docs/reference/win-docs/netstat.html` |
| 2 | 本机 `netstat /?` | 快照 `docs/reference/win-help/netstat.txt`（**2074 字节，写 stderr**，退出码 1，不入库） |

### 1.1 冲突：本机 `/?` 比官方语法行多 7 个开关，而且 `-d` 出现了两次

- 官方语法行：`netstat [-a] [-b] [-e] [-n] [-o] [-p <Protocol>] [-q] [-r] [-s] [<interval>]`
- 本机 `/?`：在上述基础上还有 `-c` `-d`（两次！）`-f` `-i` `-t` `-x` `-y`

本机 `/?` 里 `-d` 的两行说明**互相矛盾**：

```
 -d            显示每个连接分配的 DSCP 值。
 -d            显示以太网统计信息。这可以与 -s 选项结合使用。
```

**处理方式**：本清单**只收录官方文档语法行里有的开关**（`-a -b -e -n -o -p -q -r -s` 与
`<interval>`）。多出来的 7 个一律不做，理由：

1. R1 要求每个开关都能指出**唯一**的官方出处，而官方页面里没有它们；
2. `-d` 的两行说明自相矛盾，说明本机帮助文本本身可能有笔误，更加不该照着做。

这 7 个已逐条记在 §7（故意没做）。

### 2.1 `identify-owner` 的 `requiresAdmin` 依据

官方文档 `-b` 的说明里明确写（本机 `/?` 措辞相同）：

> 请注意，此选项可能很耗时，并且会失败，除非你有足够的权限。

这是**官方文字依据**，所以标了 `requiresAdmin: true`。

## 5. 本包特有的坑

1. **帮助走 stderr**（stdout 0 字节）。只看 stdout 会以为 `netstat /?` 什么都没输出。
2. **`netstat -an` 里没有本地化的表头对齐保证**：中文列宽与英文不同，
   解析输出时不要按固定列位切。
3. **`-r` 的输出前面有一段 `接口列表`**，与真正的路由表之间用一整行 `====` 分隔。
   拿路由表要跳过这一段。
4. **`-p` 在两处的取值集合不同**：单独用时是 `tcp` / `udp` / `tcpv6` / `udpv6`；
   与 `-s` 合用时还可以是 `ip` / `ipv6` / `icmp` / `icmpv6` 等。
   本清单按用途分成两个动作（`list-tcp` 用前者，`statistics` 用后者）。
5. **`-b` 的说明里那句"可能很耗时"是真的**：它要为每个连接解析出宿主可执行文件，
   本批按安全红线未实跑（需要管理员）。
6. **`-n` 很重要**：不加 `-n` 时 netstat 会对每个远端地址做反向 DNS 解析，输出会明显变慢。
   本清单多数动作默认打开 `-n`。
7. **`<interval>`（重复输出）没做**：它是"无限重播"，属于交互式用法，v1 不适合
   （要做的话得靠「取消」按钮停止，与 `ping -t` 同类）。

## 6. `/?` 与真实输出的实测形态

- `netstat /?`：**stderr** 2074 B、stdout **0 B**、退出码 **1**。
- 用法行（本机 `/?`）：`NETSTAT [-a] [-b] [-e] [-f] [-i] [-n] [-o] [-p proto] [-r] [-s] [-t] [-x] [-y] [interval]`
  —— 注意**官方语法行没有 `-f -i -t -x -y`**（见 §1.1）。
- 本机 `/?` 里 `-d` 出现两次且说明矛盾（见 §1.1）。
- `-a` 的说明里有一段描述 `-b` 输出结构的文字（"在这种情况下，可执行文件名称位于 [] 底部…"），
  这是官方文档也有的内容，不是本机特有。

## 7. 故意没做的部分与原因

| 开关 | 为什么不做 |
|---|---|
| `-c`（按端口数排序的进程列表） | 只有本机 `/?` 有，官方语法行没有 |
| `-d`（DSCP 值 / 以太网统计） | 只有本机 `/?` 有，且**两行说明自相矛盾** |
| `-f`（显示外部地址的 FQDN） | 只有本机 `/?` 有，官方语法行没有 |
| `-i`（显示 TCP 连接处于当前状态的时间） | 只有本机 `/?` 有 |
| `-t`（显示当前连接卸载状态） | 只有本机 `/?` 有 |
| `-x`（NetworkDirect 连接/侦听器/共享终结点） | 只有本机 `/?` 有 |
| `-y`（TCP 连接模板） | 只有本机 `/?` 有，且说明"无法与其他选项结合使用" |
| `<interval>`（每隔 N 秒重播） | 无限循环，属于交互式用法 |

另外：没有 `versionArgs` / `versionPattern` / `minVersion`；没有 `progress.pattern`；
没有工具包级 `category`。

## 8. 未实跑的动作与原因（安全红线）

| 动作 | 命令 | 未跑原因 |
|---|---|---|
| `identify-owner` | `netstat -b -an` | **需要管理员**（官方文档明说权限不足会失败）；且文档说它很耗时 |
| `list-tcp` 的 `udp` / `tcpv6` / `udpv6` 取值 | `netstat -p udp -an` 等 | 枚举取值经文档核对，但只实跑了默认的 `tcp`（`-an` 已覆盖 TCP） |
| `statistics` 带 `-p` 的形态 | `netstat -s -p tcp` | 文档示例有 `netstat -s -p tcp udp`；本包只做单值，未逐一实跑 |

其余 7 个只读动作全部实跑过（见 §3）。

## 9. 规范缺口 / 宿主问题

公共缺口见共用文档 §7。本包**没有额外缺口**。

**不过本包是"来源冲突时怎么办"最典型的一例**：本机 `/?`（内置于已安装版本）与官方文档
（面向 Windows Server 的最新版）不一致。playbook §0.2 说内置帮助"可作为补充，但不能作为唯一来源"，
阶段 2 又说"来源冲突时以内置帮助为准"（那是 uv 那批回灌的建议）——
**这两条在 Windows 命令上会打架**：内置帮助明显更贴合本机版本，但它有笔误（`-d` 重复）、
且官方页面才是可在公开仓库里引用的出处。
本包的处理是"**官方为准、多出来的记进 NOTES**"，并把选择理由写进清单注释。
建议 playbook 明确一条：**出处引用以官方文档为准；行为验证以内置帮助为准；两者冲突时
以官方文档为字段依据，差异记入 NOTES。**

## 10. 给后来者的提醒

- 别照本机 `/?` 补 `-c -d -f -i -t -x -y`，先在官方页面确认。
- `netstat /?` 的帮助在 stderr。写自动化脚本要读两个流。
- 想加 `<interval>` 之前先想清楚"怎么停下来"（v1 只能靠界面的取消按钮）。
