## 2. ★ 耗时实测：为什么「快速模式」不能只写 `-q 1 -p 100 -h 5`

### 2.1 原始数据（全部真跑，`CreateNoWindow=true`，即宿主式执行条件）

| 命令 | 目标 | 墙上耗时 | 输出 |
|---|---|---|---|
| `pathping 127.0.0.1` | **回环** | **26.13 s** | 455 B |
| `pathping -q 1 -h 3 127.0.0.1` | 回环 | 0.29 s | 453 B |
| `pathping -n 127.0.0.1` | 回环 | 26.08 s | 455 B |
| `pathping -q 1 -h 3 192.168.2.1` | 局域网网关 | **24.99 s** | 469 B |
| `pathping -q 1 -p 100 -h 5 192.168.2.1` | 局域网网关 | **24.39 s** | 469 B |
| `pathping -q 2 -h 5 192.168.2.1` | 局域网网关 | 24.82 s | 469 B |
| **`pathping -n -q 1 -p 100 -h 5 192.168.2.1`** | 局域网网关 | **0.14 s** | 407 B |
| **`pathping -n -q 1 -p 100 -h 5 127.0.0.1`** | 回环 | **0.13 s** | 397 B |
| `pathping -n -q 1 -h 3 129.29.29.29` | 外部 | 12.00 s | 309 B |
| `pathping -q 1 -h 3 129.29.29.29` | 外部 | 21.50 s | 331 B |
| `pathping -n -q 1 -p 100 -h 5 192.0.2.1` | 不可达 | 11.84 s | 306 B |
| `pathping -n -q 1 -p 100 -h 5 -w 200 192.0.2.1` | 不可达 | **1.50 s** | 306 B |

### 2.2 结论（这三条是本节的价值）

1. **`-q` / `-p` 几乎不影响墙上耗时。**
   任务里建议的「快速模式」`-q 1 -p 100 -h 5` 对**能通的局域网目标**实测 **24.39 秒**，
   而完全不限制（`-q 1 -h 3`）也要 **24.99 秒**——差 0.6 秒，等于没变。
   **只按文档写 `-q 1 -p 100 -h 5` 会做出一个「看起来快了、实际还是点一下等半分钟」的按钮。**

2. **真正决定快慢的是 `-n`（不做逐跳反向 DNS 解析）。**
   局域网目标：24.39 s → **0.14 s**（快约 170 倍）。外部目标：21.50 s → 12.00 s。
   耗时的主体是**给每一跳做反向名称解析**，不是探测本身。

3. **对不可达 / 被丢弃的目标，支配耗时的是 `-w`。**
   `-w 200` 把 11.84 s 压到 1.50 s（约 8 倍）。这条对「目标不通」的场景最关键——
   而那正是用户最需要诊断工具的时候。

因此本清单的 **`trace-fast` 动作 = `/n /q 1 /p 100 /h 5`**，并把 `/n` **默认勾选**，
描述里直说「只有 1 次探测、丢包率没有统计意义，用它看通不通」。
`-w` 放在同一动作的「探测参数」组里（高级折叠），让不通的目标也能快点返回。

### 2.3 顺带反推出 `-q` 的**真实默认值是 25**（文档写 100）

用「统计时长」这个自报字段当尺子（`-n` 消掉 DNS 噪声）：

| 命令 | 输出里自报的统计秒数 | 输出里的探测计数 | 墙上耗时 |
|---|---|---|---|
| `-n 127.0.0.1`（不给 `-q`） | `已耗时 25 秒` | **`0/  25 =  0%`** | 26.08 s |
| `-n -q 25 127.0.0.1` | `已耗时 6 秒` | `0/  25 =  0%` | 6.57 s |
| `-n -q 50 127.0.0.1` | `已耗时 12 秒` | `0/  50 =  0%` | 13.07 s |
| `-n -q 100 127.0.0.1` | `已耗时 25 秒` | `0/ 100 =  0%` | 26.13 s |
| `-n -q 25 -p 1000 127.0.0.1` | `已耗时 25 秒` | `0/  25 =  0%` | 25.29 s |

- 「不给 `-q`」与「`-q 25`」的输出里都写 **`0/  25`**，且墙上耗时不同（26.08 vs 6.57）——
  说明**默认确实是 25**，而 6.57 s 那次之所以快，是因为 `127.0.0.1` 只有 2 跳。
- 官方文档写 `/q` 默认 **100**，与实测**不符**。清单里以**实测 25** 为准并在 `help` 里注明差异。

## 3. 覆盖范围

| 动作 | 生成的命令 | 字段 | 危险级别 |
|---|---|---|---|
| `trace-fast` | `pathping /n /q 1 /p 100 /h 5 [目标]` | 6 | 只读 |
| `trace` | `pathping [目标]`（可加 `/n` `/q` `/h`） | 4 | 只读 |
| `trace-ipv6` | `pathping /i ::1 /6 [目标]` 等 | 6 | 只读 |
| `trace-loose-source` | `pathping /g <列表> [目标]` | 5 | 只读 |

共 **4 个动作 / 21 个字段**，全部只读诊断；无 `danger`，`requiresAdmin: false`。

### 字段风格与顺序（都实测过）

- 所有开关都是「参数 + 值必须分两个 token」的形态（官方 `/q <numqueries>`、本机 `-q num_queries`），
  所以值型开关统一用 **`style: separate`**，无值开关用 **`style: flag`**。
- **`target` 在所有动作里都声明在最后**：本机帮助的用法行把 `target_name` 写在全部开关之后
  （字段声明顺序 = argv 顺序）。
- **斜杠与破折号都实测可用**，清单按**官方文档**写 `/`：

  ```
  pathping /n /q 1 /h 3 /p 100 127.0.0.1   exit=0  out=397B   ← 官方形态
  pathping -n -q 1 -h 3 -p 100 127.0.0.1   exit=0  out=397B   ← 本机帮助形态
  ```

  两者字节数相同。**`/` 与 `-` 完全等价**（这一点与 `route` 的 `-4/-6` 情况不同：那里是「文档缺一个开关」，
  这里是「同一个开关的两种写法」）。

### 大小写敏感（官方 Remarks 提到，实测确认）

```
pathping /N 127.0.0.1   exit=1   "/N 是无效的命令选项。"
```

官方 Remarks「All parameters are case-sensitive」是真的——**大写开关会被拒绝**。

## 4. 退出码（含失败路径，全部实测）

| 命令 | 退出码 | 说明 |
|---|---|---|
| `pathping /n /q 1 /p 100 /h 5 192.168.2.1` | **0** | 成功，407 B / 15 行 |
| `pathping /n /q 1 /h 3 /6 ::1` | **0** | 成功，367 B |
| `pathping /n /q 1 /h 2 /i ::1 /6 ::1` | **0** | 成功，356 B（**`/i` 必须配 `/6`**） |
| `pathping /n /q 1 /h 1 /g 127.0.0.1 127.0.0.1` | **0** | 成功，397 B |
| `pathping`（无参数） | **1** | stdout 打帮助（601 B）。**注意：只给开关不给目标也是这个码** |
| `pathping /?` | **1** | 帮助，stdout，601 B |
| `pathping /zzz` | **1** | `/zzz 是无效的命令选项。`（626 B） |
| `pathping /N 127.0.0.1` | **1** | `/N 是无效的命令选项。`（624 B）——**大小写敏感** |
| `pathping /nope` | **1** | 被当成「没给目标」：`A target name or address must be specified.` |
| `pathping /n /q 1 /h 1 /i 127.0.0.1 127.0.0.1` | **1** | `仅 IPv6 支持选项 -i。`（73 B，IPv4 目标下用 `/i`） |

> **`/?` 与用法错误全部走 stdout**（stderr 恒为 0 B）。
> 这一点与 `route` / `nslookup` / `netstat` **相反**（那些的帮助走 stderr），
> 与 `ping` / `tracert` 一致。抓快照时两个流都要留，但 pathping 的 stderr 实测始终是空的。

## 5. 编码：实测为 OEM（936），且**两种执行条件下都是中文**

`runtime.encoding: oem`（本机 = 代码页 936）。

判定依据（带中文的输出，非纯 ASCII）：

| 执行条件 | `pathping /?` 原始字节 | 结论 |
|---|---|---|
| 真实控制台 `chcp 936` | 601 B，**204 个字节 >127**，首行 `用法: pathping …` | 中文 |
| `CreateNoWindow = true`（宿主式） | 601 B，**204 个字节 >127** | 中文 |
| `CreateNoWindow = false` | 601 B，**204 个字节 >127** | 中文 |

`pathping` 的真实诊断输出同样是中文：`通过最多 5 个跃点跟踪到 192.168.2.1 的路由`、
`正在计算统计信息，已耗时 6 秒...`、`已丢失/已发送 = Pct`、`跟踪完成。`

> **与 `route` 的关键差别（值得后来者记住）**：`route.exe` 在无控制台时会退回**英文**资源
> （2991 B 纯 ASCII，见 `plugins/route/NOTES.md` §5），而 `pathping.exe` **不会**——
> 同样条件下仍是中文。**同一台机器上同批命令的本地化行为不能互推，必须逐包实测**（R7）。

### 没验的部分与原因

| 没验 | 原因 |
|---|---|
| `-g` 松散源路由的**实际路由效果** | 本机只有回环可用来试验证参数被接受（exit 0），**没能证明报文真的按指定中间跳走**。要有真实多跳路径才能验证 |
| `-p` 的真实默认值 250 ms | 只验证了「给 `-p` 能改变节奏」（`-p 1000` 使 `-q 25` 从 6.57 s 变成 25.29 s），**没有单独测出默认值**。清单里该字段的 `placeholder` 写「官方默认 250」，是**文档值**，未用实测确认 |
| `-w` 的真实默认值 3000 ms | 同上：验证了 `-w 200` 有效（11.84→1.50 s），**没测默认值本身**。`placeholder` 的 3000 是文档值 |

## 7. 与官方文档对不上的地方（逐条）

1. **`/q` 的默认值：文档写 100，实测是 25。**
   证据见 §2.3（不给 `-q` 时输出里写 `0/  25`，且与显式 `-q 25` 行为一致）。
   清单以**实测 25** 为准，在 `help` 里写明「官方文档写 100，实测是 25」。

2. **`/i` 有一条官方没写的限制：只在 IPv6 下被接受。**
   官方参数表只说「`/i <IPaddress>` Specifies the source address」，没有任何 IPv6 限定。
   本机实测（IPv4 目标 + `/i`）返回 **exit 1**，中文提示 **`仅 IPv6 支持选项 -i。`**。
   处理方式：把 `/i` 与 `/6` 放进**同一个动作**（`trace-ipv6`），并在字段 `help` 里写明
   「必须与 `/6` 一起用：实测只给 `/i` 会被拒绝并返回 1」。这是本机实测的额外发现。

3. **官方语法行把 `/4` 与 `/6` 写成带参数**：`[/4 <IPv4>] [/6 <IPv6>]`，
   而本机 `/?` 的 `-4` / `-6` 是**无值开关**。
   实测 `pathping /n /q 1 /h 3 /p 100 /4 127.0.0.1` 与 `… /6 ::1` 都是 exit 0 且行为正确
   （`/6 ::1` 输出 `通过最多 1 个跃点跟踪到 ::1 的路由`），**没有出现「缺少参数」类错误**。
   处理方式：按**本机帮助**写成 `flag`（无值）；官方那个 `<IPv4>`/`<IPv6>` 占位符疑为文档笔误
   （对 `/4` 写 `<IPv4>` 本身就不合理——那是地址族，不是地址）。**两侧不全对齐，仅按可验证的一侧写。**

4. **官方对慢的说法与实际不符（偏乐观）**：官方 Remarks 说 busy 消息大约持续 **90 秒**
   「the time varies by hop count」，官方示例输出里写的是 `computing statistics for 125 seconds...`。
   本机实测**回环 26 秒**、局域网网关 24 秒、外部目标 12~21 秒——都短于 90 秒，
   且本机输出的中文提示是「正在计算统计信息，已耗时 N 秒...」（**按实际秒数报**，不是固定 90 秒）。
   也就是说 90 秒只是「最坏情况的量级」，清单里的耗时说明一律用**本机实测数字**。

5. **官方没写退出码**：pathping 文档没有退出码章节（已逐页核对）。清单里的 0 / 1 全部来自实测。

6. **`/?` 的输出流**：官方只说「Displays help at the command prompt」，没说哪个流。
   实测走 **stdout**（stderr 0 B）。

7. **大小写**：官方 Remarks 有「All parameters are case-sensitive」这一句，
   本机实测**成立**（`/N` exit 1）。这是少数「文档写了、实测也证实」的条目，一并记下。

## 8. 临时对象申报

**没有创建、修改或删除任何系统对象。**

- 本包的全部动作都是**只读网络诊断**：`pathping` 只发探测报文并统计，不写任何配置；
- 没有改路由表、没有改注册表、没有装任何东西；
- 冒烟用的目标都是本机回环、本机网关与保留测试网段（`192.0.2.1`、`172.16.99.99`），
  没有拿外部生产主机做长时间压测。

探针脚本写在**仓库之外**（本机专属库 `D:\AI\swpj\local\tools\`，不入库）：
`probe-route-pathping.ps1`、`probe-pathping-timing.ps1`、`probe-pathping-real.ps1`、
`probe-pathping-n.ps1`、`probe-pathping-fast.ps1`、`probe-pathping-q.ps1`、`probe-final-smoke.ps1`。
临时输出落在 `%TEMP%\route-pathping-probe\`，可随时删除。

**复核命令**：

```powershell
# 路由表没有被本包改动过（默认路由应为 2 条）

# 快速模式现在仍然是亚秒级（这是本包最该保持的性质）
```
