# robocopy 工具包说明（NOTES）

> 目标程序：`C:\Windows\System32\Robocopy.exe`（文件版本 10.0.26100.8521）—— Windows 自带。
> 清单：动作 4 个 / 字段 20 个 / 字段出处标注 **100%**
> **公共事实见 ``docs/ai/windows-commands.md``**。
> 实测环境：Windows 11 `10.0.26200`，账号 `<机器名>\<用户名>`（非管理员）。

---

## 1. 参数知识来源

| # | 来源 | 位置 |
|---|---|---|
| 1 | 官方文档 | `https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/robocopy` → 快照 `docs/reference/win-docs/robocopy.html`（参数表 **117 行**，另有 `#exit-return-codes` 一节） |
| 2 | 本机 `robocopy /?` | 快照 `docs/reference/win-help/robocopy.txt`（**8524 字节**，写 stdout，**退出码 16**，不入库） |

**开关是拿本机 `/?` 核对过的**：本清单用到的 15 个开关（`/L` `/E` `/Z` `/MT:` `/NP`
`/MIR` `/R:` `/W:` `/LOG:` `/TEE`）都能在 `robocopy.txt` 里找到对应行。
本机 `/?` 把开关分成六类（复制选项 / 复制文件限制选项 / 文件选择选项 / 重试选项 /
日志记录选项 / 作业选项），**比官方网页那份 117 行的平表更好读**，这算内置帮助优于官方文档的一处。

## 2. 覆盖范围

| 动作 id | 分组 | 开关 | 字段 | danger | requiresAdmin |
|---|---|---|---|---|---|
| `list` | 预览 | `/L` `/E` | 4 | — | 否 |
| `copy` | 复制 | `/E` `/Z` `/MT:` `/NP` | 6 | overwrite | 否 |
| `mirror` | 同步 | `/MIR` `/R:` `/W:` | 4 | **destructive** | 否 |
| `copy-with-log` | 复制 | `/E` `/LOG:` `/TEE` | 5 | overwrite | 否 |

**字段顺序两处是刻意的**：源目录 → 目标目录必须是前两个位置参数（官方语法
`robocopy <source> <destination> [<file>[ ...]] [<options>]`），本清单所有动作都把它们声明在最前。

**所有动作的 `workingDirectory` 都是 `inherit`**：`robocopy` 不会像 7z 那样"默认写到当前目录"，
它的目标目录是显式位置参数。所以**不需要**覆盖工作目录（这一点与 7z 相反，容易想错）。

## 3. 真机冒烟测试结果（含退出码）—— 本包最重要的一节

| 命令 | 退出码 | stdout | 说明 |
|---|---|---|---|
| `robocopy <src> <dst> /L`（目标为空） | **1** | 1 177 B | 尾部汇总：`文件: 1 复制:1 跳过:0 不匹配:0 失败:0` |
| `robocopy <src> <dst> /E`（首次复制） | **1** | 1 394 B | `文件: 2 复制:2 跳过:0 失败:0`，目标目录真的出现了 `a.txt` 与 `sub\b.txt` |
| `robocopy <src> <dst> /E`（再次运行，已最新） | **0** | 1 222 B | `文件: 2 复制:0 跳过:2` —— **没有文件需要复制** |
| `robocopy <src> <dst> /E`（目标里有个多余文件） | **2** | 1 259 B | `其他: 1`（多余文件），`失败: 0` |
| `robocopy <不存在> <dst> /L` | **16** | 706 B | `错误 2 (0x00000002) 正在访问源目录 … 系统找不到指定的文件。` |
| `robocopy /?` | **16** | 8 524 B | 帮助本身返回 16（它走的是"参数不全"的错误路径） |

### 3.1 这张表就是"robocopy 的退出码不是 0 才算成功"的实证

**官方 `#exit-return-codes` 一节的原文**：

> Any value equal to or greater than 8 indicates that there was at least one failure during the copy operation.

也就是说：

| 码 | 官方含义 | 实测观察 |
|---|---|---|
| 0 | 没有文件被复制、没有失败、没有不匹配（文件都已存在，复制被跳过） | ✅ 第二次 `/E` 得到 0 |
| 1 | 所有文件都复制成功 | ✅ 首次 `/E` 与 `/L` 都得到 1 |
| 2 | 目标端有多余文件；没有文件被复制 | ✅ 目标里放了 `extra.txt` 之后得到 2 |
| 3 | 部分复制；有多余文件；没有失败 | 未实测（1+2 的组合） |
| 5 / 6 / 7 | 涉及"不匹配文件"的组合 | 未实测 |
| ≥ 8 | **至少发生过一次失败** | ✅ 源不存在时得到 16 |

清单的 `exitCodes` 收录了官方表里出现的 **0 / 1 / 2 / 3 / 5 / 6 / 7 / 8**，
外加**实测发现的 16**（源目录不存在）。**0–7 全部是 `severity: ok`**，
8 与 16 是 `error`。这个映射是本包最关键的产出 —— 如果按"非 0 即错误"处理，
用户每次成功备份都会看到红色的失败提示。

### 3.2 验证过的行为差异

- `/L` 真的**不改动任何东西**（跑完目标目录仍然为空）。
- `/E` 真的**复制了子目录**（`sub\b.txt` 出现在了目标里）。
- 再跑一次 `/E` **不会重复复制**（跳过 2 个文件，退出码 0）。

## 4. 编码

stdout 实测 **OEM 代码页 936**（8524 B 帮助与 1177/1394/1222/1259/706 B 的输出都是），
`runtime.encoding: oem`。注意输出里有大量中文列名（`总数 复制 跳过 不匹配 失败 其他`、
`已结束`、`速度`），用 utf-8 解码会全乱。

## 5. 本包特有的坑

1. **退出码 0–7 都是"没有失败"**（见 §3.1）。这是本批最容易搞错的一条。
2. **`/?` 的退出码是 16** —— 因为 robocopy 的 `/?` 实际走的是"参数不全时的用法输出"路径。
3. **`/R:` 的官方默认值是 1 000 000（一百万次重试）**，`/W:` 默认 30 秒。
   也就是说默认情况下遇到一个被锁定的文件，它会**重试一百万次**。
   本清单在 `mirror` 动作里把 `/R:` 与 `/W:` 做成了字段，并在 `help` 里**强烈建议显式设小**。
   这不是清单的发明 —— 官方文档与 `/?` 都写了默认值。
4. **`/MIR` = `/E` + `/PURGE`，会删除目标端多出来的文件**。这是本工具包里最危险的动作，
   标了 `destructive` 并写了很长的 `confirmText`（提醒用户先确认源与目标没写反）。
5. **`/MT` 与 `/IPG`、`/EFSRAW` 不兼容**（官方文档写了）；`/MT` 的值必须是 1–128。
   本清单没做 `/IPG` 与 `/EFSRAW`，所以组合冲突不会发生。
6. **`/LOG:` 是"覆盖"语义，`/LOG+:` 才是追加**。本清单只做了 `/LOG:`，
   并在字段 `help` 里注明"要用追加请用 `/LOG+`（本清单未做）"。
7. **`/TEE` 必须排在 `/LOG:` 之后**（官方文档：`/TEE` writes the status output to the console
   window, as well as to the log file）。本清单的 `copy-with-log` 里 `logFile` 声明在 `tee` 之前，
   所以生成的 argv 是 `… /LOG:<路径> /TEE`。**这个顺序是刻意的**（字段顺序 = argv 顺序）。
8. **文件过滤参数（`[<file>]`）没做成字段**：它是"可选的位置参数"，默认 `*.*`。
   本清单不做它，因为"复制哪些文件"在界面上一旦做成文本框，用户很容易填错通配符，
   而 robocopy 的 `/XF` `/XD` 才是更明确的排除手段（本批也没做，见 §7）。
9. **`/NP` 关掉百分比**：robocopy 的进度是逐文件的百分比，官方也提供 `/NP` 关闭它。
   本清单把 `/NP` 做成了高级选项（输出更短）。

## 6. `/?` 与真实输出的实测形态

- `robocopy /?`：**stdout** 8524 B、stderr 0 B、**退出码 16**。
- 用法行：`用法 :: ROBOCOPY source destination [file [file]...] [options]`
- 本机 `/?` 的六类开关（**这是本机帮助优于官方网页的地方**）：
  复制选项 / 复制文件限制选项 / 文件选择选项 / 重试选项 / 日志记录选项 / 作业选项。
- 官方 `#parameters` 表有 **117 行**，`#exit-return-codes` 是独立的 `h3` 小节。
- 官方示例 9 条（含 `robocopy %USERPROFILE%\Records D:\Backup /MIR /R:2 /W:5 /LOG:C:\Logs\Backup.log`）。

## 7. 故意没做的部分与原因

| 类别 | 开关 | 为什么不做 |
|---|---|---|
| 备份模式 | `/B` `/ZB` `/EFSRAW` | `/B` 需要在备份权限下运行（本机非管理员）；`/EFSRAW` 需要 EFS 加密文件 |
| 安全/所有者 | `/SEC` `/COPYALL` `/COPY:` `/DCOPY:` `/SECFIX` `/TIMFIX` `/NOCOPY` | 需要 NTFS 权限与备份权限；`/COPY:` 的取值是组合标记，v1 表达成枚举会很别扭 |
| 危险性高的删除类 | `/PURGE` `/MOV` `/MOVE` | `/MIR` 已覆盖 `/PURGE`；`/MOV` `/MOVE` 会从源里删文件，风险高且不适合一键 |
| 文件选择 | `/A` `/M` `/IA:` `/XA:` `/XF` `/XD` `/XC` `/XN` `/XO` `/XX` `/XL` `/IS` `/IT` `/MAX:` `/MIN:` `/MAXAGE:` `/MINAGE:` `/MAXLAD:` `/MINLAD:` `/FFT` `/DST` `/XJ` `/XJD` `/XJF` `/IM` | 全是"筛选"类，组合爆炸；真实常用的是 `/XD`（排除目录）但它是"可重复的开关+值"，与 `tasklist /fi` 同类，受规范缺口限制（见 §9） |
| 监视 | `/MON:` `/MOT:` `/RH:` `/PF` | 会让 robocopy **常驻监视**，v1 不适合（没有停止机制） |
| 低可用空间 | `/LFSM` `/LFSM:n` | 冷门 |
| 作业文件 | `/JOB:` `/SAVE:` `/QUIT` `/NOSD` `/NODD` `/IF` | 作业文件是另一套配置机制，冷门 |
| 其它日志 | `/UNILOG:` `/UNILOG+:` `/TS` `/FP` `/BYTES` `/NS` `/NC` `/NFL` `/NDL` `/ETA` `/NJH` `/NJS` `/UNICODE` `/X` `/V` | 都是"输出格式微调"；本清单只做了 `/NP`（最常用的一条） |
| 文件位置参数 | `[<file>]` | 可选位置参数，默认 `*.*`；做成文本框容易填错 |
| 其它 | `/CREATE` `/FAT` `/256` `/IPG:` `/SJ` `/SL` `/NODCOPY` `/NOOFFLOAD` `/COMPRESS` `/SPARSE` `/IoMaxSize:` `/IoRate:` `/Threshold:` `/TBD` `/REG` | 冷门或与已有开关重叠 |

另外：没有 `versionArgs` / `versionPattern` / `minVersion`；没有 `progress.pattern`
（robocopy 的百分比在重定向时格式不稳定，**不凭空写正则**；`/NP` 可以关掉它）；
没有工具包级 `category`。

## 8. 未实跑的动作与原因（安全红线）

| 动作 | 命令 | 未跑原因 |
|---|---|---|
| `mirror` | `robocopy <src> <dst> /MIR` | **会删除目标端多出来的文件与目录**（`/PURGE` 语义），不可恢复 |
| `copy` / `copy-with-log` 的完整形态 | `/E` + `/Z` / `/MT:` / `/NP` / `/LOG:` / `/TEE` | 会真的复制文件；**只跑了 `/E` 与 `/L` 的形态**（在 `%TEMP%` 下的自造样本目录里） |

**实跑的形态**（都在 `%TEMP%` 的自造样本里）：`/L`（只列出）、`/E`（真的复制到临时目标，
并验证了产物与"再跑一次变为 0"）、以及故意造的多余文件（得到 2）与不存在的源（得到 16）。
`/Z` `/MT:` `/NP` `/LOG:` `/TEE` **没有单独实跑**，它们的依据是官方文档 + 本机 `/?`。

**没有在用户真实数据上跑过任何 robocopy 动作** —— 所有实测都在 `%TEMP%` 下自造的样本目录里。

## 9. 规范缺口 / 宿主问题

公共缺口见共用文档 §7。本包额外涉及：

**"可重复的开关 + 值"表达不了**：`robocopy /XD dir1 /XD dir2`、`/XF *.tmp /XF *.bak`
这类结构，与 `tasklist /fi` 是同一个缺口（见 `plugins/tasklist/NOTES.md` §9）：
`repeatable` 会让**同一个字段**产出多个 token，但不会为每个值补一个前缀。
建议：给 `repeatable` 增加"每个值各自按 prefix/separator 展开一次"的明确语义。

## 10. 给后来者的提醒

- **退出码 0–7 都是成功**，别按"非 0 即错误"处理（这是本包最容易犯的错）。
- 想加 `/R:` 时记得它默认是**一百万次重试**。
- `/MIR` 会删文件。任何与它相邻的界面文案都要提醒"先确认源与目标没写反"。
- 实测 robocopy 时**一定要在 `%TEMP%` 下造假数据**，绝不要拿真实目录当目标。
