### 1.1 官方语法行与退出码（逐字抄）

```
fc /a [/c] [/l] [/lb<n>] [/n] [/off[line]] [/t] [/u] [/w] [/<nnnn>] [<drive1>:][<path1>]<filename1> [<drive2>:][<path2>]<filename2>
fc /b [<drive1:>][<path1>]<filename1> [<drive2:>][<path2>]<filename2>
```

官方页**有独立的 `#exit codes` 小节**，逐字是：

| Exit code | Description |
|---|---|
| 0 | Files are identical. |
| 1 | **Files are different.** |
| 2 | An error occurred during comparison. |

### 1.2 与官方文档对不上的地方（如实记录）

| # | 现象 | 处理 |
|---|---|---|
| a | 官方 `#parameters` 把 `/lb<n>` 描述成 **"Sets the number of lines for the internal line buffer to N. The default length of the line buffer is 100 lines. If the files … have more than 100 consecutive differing lines, fc cancels the comparison."**（内部行缓冲，默认 **100** 行）；而本机 `/?` 描述成 **"将连续不匹配的最大值设置为指定的行数"**（最大连续不匹配行数）。两者是同一实现的两个侧面（实测行为：超过该值就报"重新同步失败。文件差异过大。"并截断输出，两种说法都解释得通）。 | 字段 `lineBuffer` 的 `doc` **两边都引**，`help` 里把两种说法并列写出，不挑一个当成"官方唯一口径"。 |
| b | 官方 `#exit codes` 只有 0/1/2 三条，**没有 0xFFFFFFFF**；而本机实测"参数不足"与 `/?` 都返回 **0xFFFFFFFF**（cmd 里 `%errorlevel%` 显示 `-1`）。 | `exitCodes` 收 4 条，第 4 条明确标注"**官方没有列，是本机实测补充的**"。 |
| c | 官方语法把"不匹配后需连续匹配的行数"写成 **`/<nnnn>`**（斜杠后跟数字）；本机 `/?` 写作 `/nnnn`，两者同义。 | 按官方写 `/<nnnn>`，字段用 `style: attached` + `prefix: "/"`（实测成立，见 §5.2）。 |
| d | 官方页 Remarks 明确提醒 **"be sure to spell out the full executable (fc.exe) since 'fc' is also an alias for Format-Custom"**。本机实测一致（`Get-Command fc` → Alias）。 | 写进 `notFoundHint` 与 `version` 动作的说明，免得用户以为工具包没生效。 |
| e | 本机 `/?` 的**语言会随控制台变化**（有控制台 = 英文，无控制台 = 中文），官方页自然不会提这件事。 | 记进 §4，并在 `sources` 里注明两种语言都抓过。 |
| f | **官方说 `/l` 能把 `.exe/.com/.sys/.obj/.lib/.bin` 顶回 ASCII 模式，本机实测顶不掉。** 官方 `/l` 原文："Compares the files in ASCII mode, line-by-line … This is the default mode for comparing files, **except** files with the following file extensions: .exe, .com, .sys, .obj, .lib, or .bin"（读法上等于"加 `/l` 就按 ASCII 比"）。本机用**同一份内容**分别复制成 8 种扩展名、`/L` 加与不加各跑一遍：六种"二进制扩展名"**加不加 `/L` 输出字节完全相同**（都是 `00000018: 61 41` 这样的二进制表，371 字节）；`.dat` 与 `.txt` 也都是文本样式（351 字节）。**`/L` 在本机这个版本上等于默认值复述，起不到"强制文本比较"的作用。** | 字段照官方写（`/L` 确实在官方语法与 `/?` 里都有），但把"本机实测它顶不掉"写进 `help`、`doc` 与这里。**没有**据此发明任何别的开关（例如去猜一个"取消扩展名推断"的参数）—— 需要强制文本比较的用户只能改扩展名，这一点如实告知。 |

## 3. ★ 本包最重要的一条：**退出码 1 不是失败** ★

这是任务点名要实测清楚的一条。官方 `#exit codes` 把 fc 的退出码定义成**"比较结论"**
而不是"命令执行状态"：

| 退出码 | 官方语义 | 本机实测（非管理员） | 界面该怎么呈现 |
|---|---|---|---|
| **0** | Files are identical | `fc a.txt a.txt` → 0；输出 `FC: 找不到差异` | 绿：两个文件相同 |
| **1** | **Files are different** | `fc cn1.txt cn2.txt` → 1；输出差异块。**这是本工具的典型正常结果** | **不是错误**：应呈现为"发现差异"（本清单把它标成 `severity: warning`），**绝不能染成红色失败** |
| **2** | An error occurred during comparison | `fc nope.txt a.txt` → 2；stderr `FC: 无法打开 … - 找不到此类文件或文件夹` | 红：真的出错了（多半是文件打不开） |
| **0xFFFFFFFF**（cmd 里显示 `-1`） | **官方没列** | `fc a.txt`（只给一个文件）→ -1，stderr `FC: 文件规范数不足`；`fc`（无参数）→ -1，同上；`fc /?` → -1 | 黄：参数不足或请求帮助 |

`0xFFFFFFFF` 是用 `Start-Process -Wait -PassThru` 的 `ExitCode` 读出来的；
用 PowerShell 的 `$LASTEXITCODE` 读同一个进程得到 `-1`，两者是同一个值的两种表示
（DWORD `0xFFFFFFFF` ↔ 有符号 `-1`）。**这三种"非 0"含义完全不同**，
所以 `exitCodes` 必须逐条写清、不能在界面上笼统地当成"失败"。

### 3.1 一个连带的重要观察

`fc` 找不到文件时**把错误写到 stderr 且 stdout 是 0 字节**；而"有差异"时
**stdout 有内容、stderr 0 字节**。也就是说：
**"退出码 1 + stdout 有输出" 才是"有差异"；"退出码 1 + stderr 有 `无效的开关`" 是参数写错了**
（实测 `fc /Z a.txt b.txt` → 退出码 **1**、stdout 有正常的差异输出、stderr 有 `FC: 无效的开关`）。
**同一个退出码 1 同时表示"有差异"和"部分开关无效"**，只有看 stderr 才能区分。
这一条已写进 `compare-text` 的 `resultNote` 提醒用户看输出区。

## 4. 编码：**OEM 代码页（本机 936，即 GBK）**，不是 UTF-8（实测原始字节，R7）

判编码用带中文的样本：造了一对**中文内容 + 中文文件名**的文件（`中文甲.txt` / `中文乙.txt`），
用 `.NET Process` + `BaseStream` 拿**原始字节**：

| 场景 | 长度 | 首字节片段 | 严格 UTF-8 解码 | 结论 |
|---|---|---|---|---|
| `fc 中文甲.txt 中文乙.txt`（无控制台） | 322 B | `d5 fd d4 da b1 c8 bd cf ce c4 bc fe 20 43 3a …` | **抛异常** | `d5 fd d4 da` = GBK 的「正在」、`b1 c8 bd cf` = 「比较」、`ce c4 bc fe` = 「文件」 → 不是 UTF-8 |
| `fc nope.txt a.txt`（错误消息，**stderr**，无控制台） | 98 B（stderr） | `46 43 3a 20 **ce de b7 a8 b4 f2 bf aa** 20 …` | **抛异常** | `ce de b7 a8` = GBK 的「无法」、`b4 f2 bf aa` = 「打开」 |
| `fc /?`（无控制台，**中文**帮助） | 906 B | `b1 c8 bd cf c1 bd b8 f6 ce c4 bc fe …` | **抛异常** | 首字符就是 GBK 的「比」 |
| `fc /Z a.txt b.txt`（错误消息，**stderr**，有控制台） | 22 B | `46 43 3a 20 49 6e 76 61 6c 69 64 20 53 77 69 74 63 68 0d 0a 0d 0a` = `FC: Invalid Switch` | 通过 | 英文版判不出代码页，所以**中文版才是判据** |

判定依据三条（与 `sort` 包同一套方法，但**结论是各自实测的**）：

1. **严格 UTF-8 解码对每一份带中文的输出都抛异常**（`new UTF8Encoding(false, true)`）。
2. **"高字节为 0 的比例"是 0%** → 不是 UTF-16LE（判定方法见 `windows-commands.md` §5.1）。
3. 用 `Encoding.GetEncoding(936)` 解码得到完全通顺的中文，用 UTF-8 解码得到 `���ڱȽ��ļ�`。

所以 `runtime.encoding: **oem**`（本机解析成 936）。写 `oem` 而不是 `gbk` 的理由：
换到英文 Windows（437）或日文 Windows（932）时同一份清单仍然正确。
即使换到"有控制台"的英文输出（纯 ASCII，1173 字节、`nonAscii = 0`），用 936 解码也逐字节正确 ——
**所以这个选择不依赖"语言会不会变"这个未定因素**。

### 4.1 ★ 输出语言会随"有没有控制台"变（本包的坑，与 `sort` 相反）★

`windows-commands.md` §5.3 记的是 `route` 的现象。fc 在本机**也有这个现象，方向也一样**，
而且**它的帮助与错误消息都跟着变**：

| 命令 | 无控制台（**宿主形态**） | 有控制台 |
|---|---|---|
| `fc /?` | **中文**，906 字节（`比较两个文件或两个文件集…`） | **英文**，1173 字节（`Compares two files or sets of files…`），`nonAscii = 0` |
| `fc /Z a.txt b.txt`（stderr） | **中文** `FC: 无效的开关`，18 字节 | **英文** `FC: Invalid Switch`，22 字节 |

判定方法（这一条我第一次也判错过，记下来）：**不能只看字节数**。
"有控制台 + 重定向到文件"与"无控制台 + 管道"必须分开量 —— 我用
`cmd /c "fc /? > out.txt"` 与 `CreateNoWindow=true` 两种条件各抓一次原始字节，
再数 `nonAscii`（127 以上字节数）与汉字个数，才把方向定下来。
在我当前的 pwsh 会话里 `chcp` 实测是 **936**，所以"中文 / 英文"不是代码页造成的，是**程序自己选资源**。

后果（三条都要记住）：

1. **判编码/判文案必须在"宿主形态（无控制台）"下做**，否则会拿到英文版，
   得出"看起来是 ASCII、无所谓编码"的错误结论。§4 的中文证据就是在无控制台下抓的。
2. **绝不能用"成功提示的措辞"判成败**。本机中文环境里"没有差异"的提示是
   `FC: 找不到差异`、二进制比较里是 `FC: <文件2> 比 <文件1> 长`，
   与官方英文页写的 `FC: no differences encountered` / `FC: earnings.bat longer than profits.bat`
   **对不上**（这是本地化，不是差异）。清单里一律用退出码判定。
3. **同一条失败可能在两种条件下是两种语言**，所以任何正则匹配错误文案的写法都不可靠。

**与 `sort` 的对照**（同批做的另一个包）：`sort /?` 在**无控制台时是中文（2196 B）**、
**有控制台时反而变英文（3683 B）**。两个包都能"变"，但**触发条件不一样**，
所以"会不会变、往哪变"必须逐个命令实测，不能按命令族推断。

## 5. 真机冒烟测试（R4，2026-10-01）

测试目录：`%TEMP%\fc-sort-probe`（**所有操作都在这里，没有碰任何用户数据**）。
夹具（除 `.exe` 那对之外都用 GBK 写入）：`a.txt` / `b.txt`（差在大小写与末尾标点）、
`a.bin` / `b.bin`（同内容副本）、`a.exe` / `b.exe`（同内容副本，用来验证"扩展名决定默认模式"）、
`tab-a.txt` / `tab-b.txt`（只差空白：Tab vs 空格）、`中文甲.txt` / `中文乙.txt`（中文文件名）。

**冒烟脚本**：48 条用例（与 `sort` 共用一个脚本），逐条用与宿主相同的模型
（`CreateNoWindow=true` + 重定向 + 立刻关 stdin）起进程，比对期望退出码。
**结果 48/48 通过（失败 0 条）**。

### 5.1 清单里 5 条 examples 的忠实复跑

| # | 动作 | argv | 退出码 | 期望值 |
|---|---|---|---|---|
| 1 | version | `/?` | **-1 (0xFFFFFFFF)** | -1 ✔（**不是 0**） |
| 2 | compare-text | `/C /N a.txt b.txt` | **1** | 1 ✔ |
| 3 | compare-text | `/W tab-a.txt tab-b.txt` | **0** | 0 ✔ |
| 4 | compare-binary | `/B a.bin b.bin` | **1** | 1 ✔ |
| 5 | compare-auto | `a.exe b.exe` | **1** | 1 ✔ |

**这里踩过一次坑并已修正**：`/W` 的第一个版本的 example 用的是 `a.txt` 与 `b.txt`，
期望退出码 0，**实测却是 1**。原因：那对文件差在 **apple 与 APPLE**，
而 `/W` 只压缩空白、**不管大小写**（官方只说 "Compresses white space"）。
于是把 example 换成一对"只差空白"的文件（`tab-a.txt` / `tab-b.txt`，实测 0），
并在该字段的 `help` 里补上"它只管空白、不管大小写"。
**这正是"examples 必须真跑"的价值** —— 光看文档写字段，示例会悄悄是错的。

### 5.2 字段风格：逐个开关把"紧贴"与"分开"都试一遍（playbook §9）

| 开关 | 官方写法 | 紧贴 | 两 token | 冒号 | 结论（本包采用） |
|---|---|---|---|---|---|
| `/A` `/C` `/N` `/T` `/U` `/L` `/OFFLINE` | 无值 | — | — | — | `style: flag`（`/OFFLINE` 与 `/OFF` 全拼都实测 exit 1 正常比较，两者等价；本包按官方语法写 `/OFFLINE`） |
| `/LB<n>` | **值紧贴** | `/LB2` → **exit 1 + `重新同步失败。文件差异过大。`**（真的生效，输出被截断） | `/LB 2` → **exit 1，但输出是"完整的普通差异"，且 stderr 为空** ⚠ **静默走偏** | `/LB:2` → exit 1 + **stderr `FC: 无效的开关`** | **`attached`** + `prefix: "/LB"` |
| `/<nnnn>` | **值紧贴** | `/0` `/1` `/2` `/3` `/5` `/10` `/100` 全部被接受；`/0` 与 `/1` 的**输出长度不同**（`/0` 把后续 8 行全打成差异，`/1` 在第一处重新同步的行停下）→ 参数确实生效 | 未试（官方语法里它就是紧贴的） | — | **`attached`** + `prefix: "/"` |

**`/LB 2` 是本包最阴的一个坑**（playbook §10 第 11 条"不报错但行为不同"的又一实例）：

```
argv: /LB 2 <文件1> <文件2>      ← "看起来"是设缓冲为 2
实测: 退出码 1、stderr 空、输出是一份看起来完全正常的差异报告
真相: "2" 被当成了第一个要比较的**文件名**，实际生成的是 /LB + 文件名1 + 文件名2
```

它**不报错**（因为 `/LB` 单独出现时 fc 按默认值 100 继续工作），
只有把"紧贴"和"分开"两种写法都跑一遍、并对比输出长度才会发现。
本包因此必须用 `style: attached`（生成 `/LB2`），**绝不能写成 `separate`**。

`/<nnnn>` 的取值行为实测（一对前 6 行全不同、后 2 行相同的文件，8 行输入）：

| argv | 输出里最后一行差异 | 结论 |
|---|---|---|
| `/0` | `SAME-B` | 值 0 = 不做重新同步，把后面全部算差异 |
| `/1` | `SAME-A` | 从 1 开始行为就一致（官方默认值是 2） |
| `/2`、`/3`、`/5`、`/10`、`/100`、不给值 | `SAME-A` | 值 ≥1 时输出一致 |

### 5.3 退出码：含失败路径的逐条实测

| argv | 退出码 | stdout | stderr |
|---|---|---|---|
| `a.txt a.txt`（相同） | **0** | `正在比较文件 …` + `FC: 找不到差异` | — |
| `cn1.txt cn2.txt`（文本比较，有差异） | **1** | 差异块 | — |
| `/B a.bin b.bin`（二进制，有差异） | **1** | `00000018: 61 41` 这样的地址-字节表 | — |
| `a.exe b.exe`（**扩展名决定默认走二进制**） | **1** | 二进制样式（`000000…: XX YY`），证明默认模式确实按扩展名切换 | — |
| `/Z a.txt b.txt`（非法开关） | **1** | 差异块 | 无控制台下：`FC: 无效的开关`（18 B）；有控制台下：`FC: Invalid Switch`（22 B） |
| `/LB:2 a.txt b.txt`（冒号） | **1** | 差异块 | `FC: 无效的开关` |
| `/OFF a.txt b.txt` 与 `/OFFLINE a.txt b.txt` | **1** | 差异块（与不加时一致） | — |
| `nope1.txt a.txt`（文件不存在） | **2** | 空 | `FC: 无法打开 … - 找不到此类文件或文件夹` |
| `/B nope1.txt a.txt` | **2** | 空 | 同上 |
| `<目录> a.txt`（目录当文件） | **2** | 空 | `FC: 无法打开 <目录> - 找不到此类文件或文件夹` |
| `a.txt`（只给一个文件） | **-1** | 空 | `FC: 文件规范数不足` |
| （无参数） | **-1** | 空 | `FC: 文件规范数不足` |
| `/?` | **-1** | 906 B 帮助（中文） | — |
| `*.bat new.bat`（通配符，3 个文件逐个比） | **1** | 三组比较结果（前一组"找不到差异"、后两组有差异） | — |

`exitCodes` 按 0 / 1 / 2 / -1 四条写；第 4 条明确标注"官方没有列，本机实测补充"。

### 5.4 各开关的"到底干了什么"（都用真实文件验证过）

| 开关 | 实测证据 |
|---|---|
| `/C` 忽略大小写 | 同一对文件（差在 apple/APPLE）加 `/C` 后，差异块里 **apple 那一段消失**，只剩 `zebra` 与 `zebra!` 那段 → 真的忽略大小写 |
| `/A` 只显示首末行 | 与不加 `/A` 输出相比，差异块被压缩到每处只留首末两行 |
| `/N` 显示行号 | 输出变成 `    1:  第一行 中文内容` 这种"右对齐行号 + 冒号"的形态 |
| `/T` 不展开 Tab | 同一对"Tab vs 8 空格"的文件：不加 `/T` 时 Tab 被当成 8 个空格（输出里 `a       b` 对 `a  b` 判为差异）；加 `/T` 后 Tab 原样保留（输出里能看到真的制表符）→ **`/T` 是"关闭"语义的开关**，默认才是"把 Tab 当空格" |
| `/W` 压缩空白 | 同一对文件加 `/W` → 退出码 **0**、`FC: 找不到差异` → 真的把空白差异吞掉了 |
| `/U` UNICODE | 拿普通 GBK 文本文件加 `/U`，**输出变成一堆问号**（`????????????灡汰?????敺牢?`）→ 它只适合**本来就是 UTF-16** 的文件。已写进字段 `help` 作为警告 |
| `/L` ASCII 模式 | **⚠ 实测与官方说法不符**：拿**同一份内容**复制成 8 种扩展名逐对比较，六种"二进制扩展名"（`.exe` `.com` `.sys` `.obj` `.lib` `.bin`）**加不加 `/L` 的输出字节完全相同**（371 字节，都是 `00000018: 61 41` 这样的二进制表）；`.dat` 与 `.txt` 无论加不加 `/L` 都是文本样式（351 字节）。结论：**`/L` 在本机没有"顶掉扩展名自动推断"的效果**，它只是把默认模式又说了一遍。已在字段 `help` 与 §1.2(f) 写明 |
| `/LB2` 行缓冲 | 真的改变行为（触发 `重新同步失败。文件差异过大。` 并截断输出） |
| `/<nnnn>` 重新同步行数 | `/0` 与 `/1` 输出长度不同（§5.2 的表）→ 真的生效 |
| `/OFFLINE` | **只验证了"能接受且不改变比较结果"**（`/OFF`、`/OFFLINE` 都退出码 1、输出与不加时字节级一致）。**没有验证到它的语义** —— 本机没有带脱机属性的文件，也没去构造（构造脱机属性属于改文件系统状态，本包的红线是不碰用户文件）。已在字段 `help` 里如实写明 |

### 5.5 没冒烟的动作

**没有"完全没跑"的动作** —— 4 个动作的 examples 全部实跑过。但有三条限定必须说清：

1. **冒烟是在宿主之外**用 `.NET Process` 直接拼 argv 跑的（本次不能改宿主、也不该启动 GUI）。
   宿主链路（表单 → `ArgvBuilder` → `ProcessRunner`）**没有**跑 fc。
   不过本包的字段形状很朴素（`positional` + `flag` + 一个 `attached` 数字），
   与已验证的 `robocopy` / `tar` 包同类，且 `ArgvBuilder` 的展开规则与 §5.1 用的 argv 一致。
2. **`/OFFLINE` 的语义没有实测**（见 §5.4 最后一行）—— 只验证了语法可接受。
3. **`/<nnnn>`（resyncLines）字段的"数字 → `/<值>` token"这一步没有在宿主里跑过**：
   实测用的是手工拼的 `/3`。字段写成 `style: attached` + `prefix: "/"` + `type: number`，
   按规范 §4 的展开规则应当生成单个 token `/<值>`，与实测的 `/3` 等价；但宿主真跑没验证。
   同类的 `lineBuffer`（`/LB` + 数字）**有**直接实测证据（`/LB2`）。
4. 大文件 / 超过行缓冲的场景只做到"用小文件模拟出缓冲耗尽"（`/LB2` 那条），
   **没有拿真正的 100+ 行差异文件跑过**。

## 6. 故意没做的部分（给后来者的地图）

| 没做 | 原因 |
|---|---|
| **`/OFF` 这个缩写形态** | 官方语法写 `/off[line]`，即 `/off` 与 `/offline` 都合法（本机两个都实测 exit 1 正常）。清单只收录**官方语法行里的最完整写法 `/OFFLINE`**，避免"一个开关两个字段"。 |
| `/B` 与文本开关的组合字段 | 官方把语法**分成两条**（`fc /a [/c] [/l] …` 与 `fc /b …`），/B 与 /A /C /L /N /T /U /W /LB 是互斥的。清单用**两个独立动作**（`compare-binary` 与 `compare-text`）来保证界面永远拼不出矛盾组合，而不是给字段加 `visibleWhen`（规范 §4 明确写了 `visibleWhen` **v1 宿主尚未实现**）。 |
| `progress.pattern` | fc 没有进度输出（一次性算完再打印差异），**不凭印象编正则**（R1）。 |
| `nextSteps` / `quickActions` | 没有能从输出里可靠判定的"下一步"（"发现差异"之后该干什么取决于用户在干什么）。按规范 §2.2 第 2 条，**不写**好过写一个 0 命中的正则。 |
| `danger` / `confirmText` | **fc 完全是只读的**：只读两个文件、只打印差异，不改任何文件。所以所有动作都不写 `danger`。 |
| `execution: info` / `terminal` | 没有会弹窗或需要交互的动作。 |
| `requiresAdmin` | **不需要**，且是实测的（§2）。包级写 `false`，动作级不写。 |
| 目录级比较（`fc <目录1> <目录2>` 那种"表达式"形态） | 官方语法里两个位置参数都是 `[[<drive1>:][<path1>]]<filename1>`（**文件**），本机实测把目录当第一个参数也是 `FC: 无法打开 … - 找不到此类文件或文件夹`（exit 2）。所以**没有**做成"选两个目录"的动作 —— 那会是发明参数。 |
| `minVersion` | 没有版本开关（`/?` 不是版本输出），无从比较 → 不写（与 Windows 命令集口径一致）。 |

## 7. 与同批 `sort` 包的关系（避免重复，也避免误抄）

`fc` 与 `sort` 是同一批做的两个 Windows 自带命令包（`fc.exe` 与 `sort.exe` 的文件版本
都是 `10.0.26100.8875`），下面这些结论**两边都成立、但必须各自实测**：

| 事实 | fc | sort |
|---|---|---|
| 输出编码（**宿主形态：无控制台**） | **oem / GBK 936**（§4） | **oem / GBK 936**（`plugins/sort/NOTES.md` §4） |
| 无控制台（宿主形态）时的语言 | **中文**（`/?` 906 B、`FC: 无效的开关` 18 B） | **中文**（`/?` 2196 B） |
| 有控制台时的语言 | **英文**（`/?` 1173 B、`FC: Invalid Switch` 22 B） | **英文**（`/?` 3683 B，全 ASCII；但走管道时仍是中文 2196 B） |
| 比较/排序结果写哪 | stdout | stdout |
| `/?` 写哪 | stdout | stdout |
| 错误写哪 | stderr | stderr |
| `/?` 退出码 | **-1（0xFFFFFFFF）** | **0** |
| 是否需要管理员 | 否 | 否 |
| 版本开关 | 没有（用 `/?`） | 没有（用 `/?`） |
| 位置参数是否可用通配符 | **可以**（`*` / `?`，实测 `*.bat new.bat`） | **不可以**（实测 exit 1 + `文件名、目录名或卷标语法不正确。`） |
| 默认从哪读输入 | 必须给两个文件名（官方语法里两个都 required） | **默认读标准输入**，文件名可选 ← 所以它才有"裸跑静默无输出"的问题 |

**不要互抄**：`/?` 的退出码、能不能用通配符、"输入是不是必填"，
这三个问题的答案两个包各不相同；语言切换的触发条件也要各自看清（§4.1 与 sort NOTES §4.1）。
